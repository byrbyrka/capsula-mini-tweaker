# Твикер Капсулы Мини 1.0.0

Управление кнопками, звуком, экраном и световым кольцом VK Капсулы Мини на Alpine Linux. Программа написана на C и устанавливается одним бинарным файлом для ARM64 / musl.

Для открытия меню запустите на колонке **без аргументов**:

```sh
capsule-tweaker
```

На колонке не нужны Python, виртуальное окружение, компилятор или дополнительные библиотеки. Мордашка рисуется через sysfs, звук регулируется через ioctl ALSA. Перерисовка экрана и изменение громкости не запускают `clockdisp`, `sleep`, `dd` или `amixer`.

## Установка и обновление

Скачайте проект в папку `capsule-controls`:

```sh
git clone https://github.com/byrbyrka/capsula-mini-tweaker.git capsule-controls
```

На компьютере, из каталога с папкой `capsule-controls`:

```sh
scp -r ./capsule-controls root@192.168.0.134:/root/
```

Замените `192.168.0.134` на IP своей колонки. Если папка находится в другом месте, укажите полный путь к ней в кавычках.

На колонке от `root`:

```sh
sh /root/capsule-controls/install.sh
capsule-tweaker
```

В [`bin/`](bin/) лежит готовый бинарник для ARM64 Alpine. Перекомпиляция на колонке не требуется. Установщик проверяет оборудование, останавливает прежнюю службу, импортирует известные параметры старого JSON и сохраняет громкость, мьют и выбранный экран.

При переходе с Python-твикера его установленные файлы из `/usr/local/lib/capsule-controls` удаляются. Пакет `python3` автоматически не удаляется, поскольку он может использоваться другими программами.

При первой установке отключается звук загрузки; при обновлении сохраняется предыдущий выбор. Прошивка, ядро, Wi-Fi и `flasher.sh` не меняются.

Из штатной прошивки используются `ringled`, `wget`, сертификаты CA и часовые пояса. Недостающие сертификаты и `tzdata` установщик добавит через `apk`. Сам твикер динамически связан только с musl libc.

## Кнопки

| Кнопка | Действие |
| --- | --- |
| **Плюс / минус** | Громкость от 0 до 100 с шагом 5 |
| **Микрофон** | Мьют динамика; повторное касание возвращает звук |
| **Действие** | Переключение экранов: доллар → часы → мордашка → доллар |
| **Мьют + действие** | Вход в настройку кольца |

Одиночные мьют и действие срабатывают при отпускании кнопки. Это позволяет распознать комбинацию в любом порядке, не выполняя два одиночных действия.

Плюс и минус снимают мьют. Нулевая громкость аппаратно отключает динамик. Мьют усилителя относится к динамику: выход 3,5 мм его переключатель не глушит.

## Настройка кольца кнопками

1. Зажмите **мьют + действие** вместе, затем отпустите обе кнопки.
2. На экране появится `r` и номер эффекта.
3. Выбирайте эффект кнопками **плюс / минус** с предпросмотром.
4. Нажмите **действие**, чтобы подтвердить выбор и вернуться к обычному управлению.

Одиночное нажатие **мьюта** отменяет выбор и возвращает прежний эффект.

| Номер | Эффект |
| --- | --- |
| `0` | Выключено |
| `1` | Радуга |
| `2` | Огонь |
| `3` | Постоянный цвет |
| `4–19` | Свои пресеты, если они созданы |

Комбинация не меняет громкость, мьют или выбранный экран. В режиме настройки плюс и минус выбирают эффект и не регулируют звук.

Предпросмотр кольца временно заменяет красный индикатор; состояние звука остаётся прежним. После выхода мьют снова имеет приоритет. Если отключить питание во время предпросмотра, останется ранее подтверждённый эффект.

## Свои пресеты кольца

Откройте **`capsule-tweaker` → 10 «Настройки кольца» → 8 «Свои пресеты» → 1 «Создать»**.

Можно хранить **до 16 пресетов**, в каждом — **до 12 кадров**. Один кадр задаёт постоянный рисунок; несколько кадров сменяются по кругу.

### Редактор пресета

| Пункт | Настройка |
| --- | --- |
| `1` | Уникальное имя: до 48 байт, обычно до 24 русских букв |
| `2` | Тип эффекта: свои кадры, радуга, огонь или выключено |
| `3` | Собственная яркость: 0–100% |
| `4` | Время оборота радуги: 500–30000 мс |
| `5` | Длительность кадра: 250–10000 мс |
| `6` | Редактор цветов выбранного кадра |
| `7` | Добавить копию последнего кадра |
| `8` | Удалить кадр |
| `9` | Сохранить |
| `10` | Сохранить и включить |
| `0` | Отменить изменения |

Каждый из 12 светодиодов имеет свой цвет в формате `RRGGBB`:

| Значение | Цвет |
| --- | --- |
| `ff0000` | Красный |
| `0000ff` | Синий |
| `000000` | Выключен |

Диоды пронумерованы от `0` до `11`; передний центр — `6` до применения калибровки `ring_front`. Редактор позволяет залить все диоды одним цветом или сдвинуть рисунок на один диод.

### Примеры анимаций

**Красно-синее мигание:**

1. В пункте `6` залейте первый кадр красным.
2. Пунктом `7` добавьте второй кадр.
3. В пункте `6` выберите кадр `2` и залейте его синим.
4. Задайте длительность кадра пунктом `5`.
5. Выберите `10` — «Сохранить и включить».

**Бегущая точка:** создайте кадр с одним горящим диодом, затем добавляйте его копии и сдвигайте рисунок в каждом новом кадре.

### Сохранение и переключение

Создание, редактирование и удаление доступны через то же меню. Пресеты сразу записываются в `/etc/capsule-tweaker.conf` и сохраняются после перезапуска и обновления. Выбор активного эффекта сохраняется с задержкой **2 секунды**.

Свои пресеты доступны и при настройке кнопками **мьют + действие**. При удалении выбранного пресета включается «выключено», а номера следующих пресетов сдвигаются.

Перед редактированием пресетов через CLI завершите настройку кнопками: подтвердите выбор кнопкой действия или отмените мьютом.

Шкала громкости временно заменяет рисунок, затем возвращает его. Мьют имеет приоритет над пресетом и показывает только передние красные диоды. Яркость шкалы и мьюта задаётся общей настройкой кольца, отдельно от пресета.

Для постоянного рисунка `ringled` вызывается только при изменении кадра. Для своей анимации — на смене кадров, не чаще **4 раз в секунду**. Планирование работает в существующем C-процессе; отдельная постоянная служба не добавляется. Для меньшей нагрузки выбирайте один кадр или увеличивайте его длительность.

## Подсветка и экран

### Мьют и шкала громкости

При мьюте постоянно горят только передние красные светодиоды `5`, `6`, `7`. Надпись `OFF` не выводится. Позиция и цвет взяты из `mic_off.json` стоковой прошивки.

При регулировке громкости на **1,5 секунды** появляется штатная шкала `volume.json`: чем выше громкость, тем больше заполнение. При нуле шкала пустая. Затем восстанавливается выбранный эффект. При мьюте красный участок имеет приоритет над эффектом и откликом кнопки действия.

По умолчанию постоянные эффекты кольца выключены: в покое дополнительного процесса нет. Для радуги или огня запускается один нативный `ringled` с 8 кадрами в секунду. При мьюте и показе шкалы процесс останавливается, после завершения отклика запускается снова.

### Мордашка и часы

Мордашка работает внутри процесса C без запуска `clockdisp`. Доступны `wink`, `blink`, `sleep`, `wow`, `angry` и `idle`; время кадра настраивается. Сегменты и маски соответствуют `clockdisp` из приложенной прошивки.

**`idle` — намеренно неподвижная мордашка.** Для подмигивания выберите **4 «Настройки экрана и мордашки» → 4 «Выбрать мордашку» → 0 «wink»**.

Часы используют системное время, по умолчанию `Europe/Moscow`. Его синхронизация остаётся за `chronyd`.

После смены `map_seg7` повторно записывается `message`, чтобы драйвер обновил видимые сегменты. При ошибке записи кадр повторяется; неподвижный кадр лишних записей не создаёт. После ошибки записи яркости или двоеточия значение повторно отправляется драйверу.

### Курс доллара

Источник — [официальный курс USD/RUB ЦБ РФ](https://www.cbr.ru/scripts/XML_daily.asp).

Курс проверяется раз в **6 часов** отдельным `wget` с ограничением времени. Кнопки во время загрузки работают. При ошибке остаётся кеш и выполняется повтор через **15 минут**.

До 100 рублей показываются копейки с нижней точкой двоеточия; от 100 — округлённые целые рубли. При отсутствии курса выводится `----`.

## CLI-меню

| Пункт | Действие |
| --- | --- |
| `1` | Громкость 0–100, шаг 5 |
| `2` | Мьют |
| `3` | Режим экрана |
| `4` | Яркость и ток дисплея, мордашка, время кадра, кнопка действия |
| `5` | Включить или выключить звук при старте |
| `6` | Включить или выключить службу и автозапуск |
| `7` | Перезапустить службу |
| `8` | Диагностика и данные курса |
| `9` | Удалить твикер и восстановить команды автозапуска |
| `10` | Эффект кольца, яркость, длительность шкалы, скорость радуги, постоянный цвет, положение переднего участка, свои пресеты |
| `0` | Закрыть меню; служба продолжит работу |

Яркость кольца по умолчанию — **50%**. Начальный передний центр — `6`: светодиоды `5–7`.

Настройки сохраняются через **2 секунды** после изменения и при нормальной остановке, чтобы не писать во flash при каждом касании. Последние изменения могут потеряться при внезапном отключении питания в эти 2 секунды. Сами пользовательские пресеты сохраняются сразу после команды «Сохранить».

Проверяются диапазоны импортированных настроек и пересечения кодов кнопок. Некорректный старый конфиг отклоняется до обращения к оборудованию.

## Сборка

Сборка на компьютере из папки проекта:

```sh
make
```

Сборка для ARM64:

```sh
CAPSULE_SYSROOT=/path/to/alpine-aarch64-sysroot sh tools/build-arm64.sh
```

`CAPSULE_SYSROOT` должен указывать на sysroot Alpine aarch64 с `musl-dev`, `linux-headers` и musl из прошивки. На компьютере используются `clang`, `lld` и `llvm-strip`. Компилятор на колонку не устанавливается.

## Проверки и ресурсы

Из папки проекта:

```sh
make test
```

C-тесты проверяют состояние, миграцию, парсер курса, шкалу, порядок ioctl, полный мьют при нуле, комбинации кнопок в обоих порядках, подтверждение и отмену настройки кольца, пределы громкости и восстановление стартовых файлов.

Отдельные тесты пресетов проверяют формат, лимиты, дубли имён, полную конфигурацию с 16 пресетами, кадры, удаление и переключение кнопками. Тест дисплея моделирует обновление видимых сегментов только после записи `message` и проверяет все мордашки, повтор кадра после ошибки и возврат к мордашке после временного экрана громкости.

Интеграционный тест запускает отдельный процесс C с эмуляцией входных событий, sysfs и ALSA. Он проверяет меню, дочерние процессы и сохранение, создаёт свою анимацию в CLI, проверяет её кадры и приоритеты и перезапускает службу для проверки сохранения пресета. Python нужен только для этого теста на компьютере; в установке на колонку его нет.

Дополнительно выполнены проверки AddressSanitizer/UBSan и статический анализ Clang. ARM64-бинарник и C-тесты запускались через QEMU с musl из приложенного rootfs. **Аппаратное испытание на физической колонке пока не выполнено.**

Размер бинарника и замеры процесса записаны в [`VERIFICATION.json`](VERIFICATION.json). RSS и CPU измерены на компьютере x86_64 с glibc в тестовом окружении; это не замер на ARM64-капсуле. Нулевой расход процессорного времени за короткий интервал означает расход ниже разрешения счётчика, а не абсолютное отсутствие работы.
